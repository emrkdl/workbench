02 무엇을 만들었나 4장 중 2장

설계 파일 한 장이 화면에 닿기까지

가운데에 공통 설계 모델(CDM). 설계 파일을 읽어 이 모양으로 바꾸고, 그 뒤로는 어느 화면도 원본 파일을 다시 열지 않음. 서버 코드와 화면 코드는 이 모델 정의에서 자동 생성 — 손으로 두 번 적으면 어긋나므로.

03 어디까지 왔나 4장 중 3장

무엇으로 확인하나

서버는 파서 결과 대조 · 적재 · 응답 형식 · 권한을 시험 17건으로 지킴. 화면은 타입 검사와 배포용 빌드를 변경마다 통과. 두 곳이 같은 약속을 지키는지는 응답 형식 시험이 담당.

폐쇄망 전제

동작 중에 바깥 인터넷을 보지 않음. 글꼴도 스크립트도 전부 안에. 배포는 묶음 파일 하나를 반입해 서버에서 올리면 끝.

04 원칙과 다음 4장 중 4장

화면은 설계 파일이 아는 것까지만

이 화면을 믿고 판단이 내려짐. 그래서 모르는 값을 그럴듯하게 채우지 않는 것이 기능 하나 더 붙이는 것보다 우선.

없는 값은 비워 둠

부품 수명(단종 여부)과 제조사는 설계 파일에 없는 값 — 구매 시스템이 붙어야 아는 것. 화면과 표에서 전부 제거하고 자리만 남김. 연결되면 그때 채워짐.

단위는 하나로

내부는 나노미터 정수, 화면 표기는 mm 하나로 통일. 소수로 다루면 안 움직인 부품이 비교에서 "이동함"으로 잡히고, mil 과 µm 을 섞으면 읽는 사람이 매번 환산.

색을 다시 배우지 않게

부품 색은 사내 배치 도구, 배선 색과 비아 표시는 사내 라우팅 엔진을 그대로 따름. 같은 보드를 두 도구에서 보는 사람이 색을 다시 익힐 이유가 없음.

설명글보다 화면

화면마다 붙어 있던 해설 문단을 제거. 제목과 값이 이미 말하는 것을 되풀이하고 있었고, 길이가 제각각이라 눈이 걸림.
